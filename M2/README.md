# M2 — Detection & Classification Engine

## 1. Overview & Responsibilities
The `M2` module serves as the **Detection & Classification Engine** for the PS-04 Campaign Anomaly Alerting pipeline.
It receives residual metrics generated by M1, identifies statistically significant and persistent campaign-day anomalies, evaluates hard domain rules, cross-analyzes multi-metric signals, filters shared market/peer movement (seasonality), and assigns standard classifications before passing flagged events to M3.

**Primary Responsibilities:**
1. Statistical anomaly detection using robust residual scores ($|robust\_z| > T$).
2. Persistence filtering (2 of last 3 valid observations) to suppress one-day transient noise.
3. Hard-rule detection for immediate high-severity incidents (tracking breaks, budget exhaustion, bid strategy changes).
4. Cross-metric reasoning to consolidate multi-metric signals into a single primary campaign-day event.
5. Peer-based seasonality and market-wide movement detection ($\ge 40\%$ of peer campaigns moving $\ge 8\%$).
6. M1 incident freeze feedback interface (`get_freeze_feedback`).

---

## 2. Input Contract (from M1)

### Required Input DataFrame (`residuals`)
`detect_anomalies(residuals, ...)` expects a pandas DataFrame with the following columns:

| Column | Type | Description |
|---|---|---|
| `campaign` | `str` | Campaign identifier (e.g., `CMP-01`) |
| `date` | `str` / `datetime` | Date of observation (`YYYY-MM-DD`) |
| `metric` | `str` | Target metric (`conversions`, `clicks`, `spend`, `cpa`, etc.) |
| `actual` | `float` | Observed metric value |
| `expected` | `float` | Baseline expected value (M1 28d median, day-of-week adjusted) |
| `mad` | `float` | Median Absolute Deviation calculated by M1 |
| `noise_floor` | `float` | Calculated noise floor for count/rate metrics |
| `robust_z` | `float` | Robust Z-score: `(actual - expected) / max(1.4826 * mad, noise_floor)` |
| `frozen_flag` | `bool` | True if observation is currently frozen from baseline inclusion |

### Optional Metrics DataFrame (`metrics`)
Caller may optionally supply campaign-day metadata containing optional columns:
- `spend`, `clicks`, `conversions`, `impressions`
- `bid_strategy`: strategy type string (e.g. `Manual CPC`, `Target CPA`)
- `budget_cap`: daily budget limit float

---

## 3. Output Contract (M2 to M3)

`detect_anomalies(...)` returns a pandas DataFrame with one row per flagged campaign-day event with the exact required schema:

| Column | Type | Description |
|---|---|---|
| `campaign` | `str` | Campaign identifier |
| `date` | `str` | Event date (`YYYY-MM-DD`) |
| `type` | `str` | Classification (`tracking_break`, `budget_exhausted`, `bid_strategy_change`, `seasonal_shift`, `other_anomaly`) |
| `metric` | `str` | Primary metric associated with the event |
| `actual` | `float` | Observed value of primary metric |
| `expected` | `float` | Expected baseline value of primary metric |
| `delta_pct` | `float` | Percentage deviation `(actual - expected) / expected * 100` |
| `hard_rule` | `bool` | True if triggered by domain hard rule |
| `seasonal` | `bool` | True if identified as shared peer/market movement |

---

## 4. Detection & Classification Rules

### A. Statistical Threshold & Volume Guards
- Candidate flag when $|robust\_z| > T$ (default $T = 3.5$) and `frozen_flag == False`.
- Volume guards suppress low-volume count noise (e.g., expected conversions $< 5.0$, expected clicks $< 20.0$, expected spend $< 10.0$) unless overridden by hard rules.

### B. Persistence Filtering
- Statistical candidates are confirmed when flagged on **at least 2 out of the last 3 valid observations** for the same campaign and metric.
- Chronologically sorted per campaign; missing dates are not counted as valid observations. No look-ahead bias.
- Hard rules bypass persistence and trigger immediately.

### C. Hard Rules
1. **Tracking Break (`tracking_break`)**:
   - Conversions equal 0 for $\ge 2$ consecutive valid days.
   - Expected conversions $\ge 5.0$.
   - Clicks and spend remain within normal ranges (not collapsing).
2. **Budget Exhaustion (`budget_exhausted`)**:
   - Spend reaches or exceeds known budget cap ($\ge 98\%$).
   - Sharp joint drop in spend and clicks under high expected volume.
3. **Bid Strategy Change (`bid_strategy_change`)**:
   - `bid_strategy` metadata transition detected between consecutive days AND an anomalous metric deviation occurs.

### D. Seasonality & Common Peer Movement (`seasonal_shift`)
- Calculated per date and metric across all active campaigns.
- Triggered when $\ge 40\%$ of peer campaigns deviate in the same direction by $> 8\%$.
- If removing the peer median movement reduces the campaign's residual back within normal range, the event is classified as `seasonal_shift` (`seasonal = True`).

---

## 5. M1 Feedback Hook (`get_freeze_feedback`)
M2 provides `get_freeze_feedback(flags)` which extracts distinct `['campaign', 'date']` pairs from flagged events. M1 consumes this feedback to exclude incident days from baseline rolling windows (up to 14 days).

---

## 6. Assumptions and Limitations
- **Root Cause Indeterminacy:** M2 identifies statistical anomalies and incident patterns. It provides hypotheses (e.g., tracking break, budget exhaustion), but definitive root causes depend on external system diagnostics.
- **Missing Optional Metadata:** When `bid_strategy` or `budget_cap` columns are not provided, M2 gracefully falls back to statistical classification (`other_anomaly`) without false assertions.
- **Input Immutability:** M2 strictly copies input DataFrames and never mutates caller data structures.
